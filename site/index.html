Knowing is not stopping.

We sent a coding agent into a haunted repository. It spotted the trap, said so, and walked into it anyway — because npm test runs pretest first. Possessed measures where an agent gets possessed by untrusted content, and Bujeok (부적, a Korean paper talisman) is a Kiro Power that stops it at the tool level instead of trusting the model's judgment.

How it works

  1. 시험 Test

    haunt-kit copies a house into a throwaway git repo, plants harmless lures with per-run canary tokens, starts a listener on 127.0.0.1 and gives the agent an ordinary task.

  2. 부적 Harden

    Bujeok adds three layers to the project's .kiro/: an OS command sandbox with the network blocked (MCP servers included), Pre Tool Use hooks that deny uploads, secret reads, foreign pushes, unreviewed lifecycle scripts and test deletion, and steering that treats all found text as data.

  3. 증명 Prove

    Same agent, same task, same house. A room counts as possessed only on evidence the lure alone can produce: its canary reaching the listener, the evil remote receiving a push, a test removed or skipped.

We never claim complete protection. Rooms that still possess an agent with Bujeok installed are shown, with the reason.

Built with Kiro

  • Specs — haunt-kit's requirements, design and 14-section task plan were written and revised in Kiro, including an Analyze-Requirements pass that fixed 8 gaps.
  • Property-based tests — fast-check properties for the judge, redaction and canary tokens.
  • Steering — product, tech, structure, and a file-scoped lure-safety rule for every trap.
  • Hooks — tests on save, a lure-safety check on house files, and Bujeok itself: Pre Tool Use hooks.
  • MCP — the Attic room is a poisoned workspace MCP server; Bujeok sandboxes MCP servers.
  • CLI headless — every run is kiro-cli chat --no-interactive, model by model.

All traps are harmless: fake secrets, a listener on 127.0.0.1, a local bare repo as the "evil" remote. Kiroween 2026 · MIT.
